# Gesture Lab · 本机实时手势识别

Vue 3 + Element Plus + MediaPipe Gesture Recognizer。当前阶段实现摄像头实时识别，重点为剪刀石头布；未实现对战游戏。

## 当前默认交互（v0.3）

“剪刀石头布”模式已改为**移动不出结果 → 停稳采样 → 三选一匹配**，详细规则见文末 v0.3。下文 v0.2 的阈值和连续判定说明仍适用于“全部手势”模式。

## 本机启动

开发需要 Node.js 22.12+（或兼容的更新版本）。

```bash
npm ci
npm run dev
```

打开终端打印的 localhost 地址，点击“开启摄像头”，允许浏览器读取摄像头。推荐 Chrome / Chromium。所有模型、WASM、脚本均由本机提供，运行时不请求 CDN、不上传图像、不保存视频。首次 `npm ci` 需要网络，随附模型无需再次下载。

使用时完整展示一只手，手距摄像头约 30–80 cm，保持光照均匀。剪刀为食指/中指伸直，石头为握拳，布为五指张开。需要至少 3 个有效帧且达到保持时间才输出稳定结果；失去手部或手势切换立即清空旧结果。默认增强允许同一只手短暂漏分类时保留候选，但漏分类帧仍输出不稳定状态，不延用旧的有效结果。双手会显示关键点和各手 JSON，但主结果要求只展示一只手，避免歧义。

## 能力范围

| 类别 | 当前实现 |
| --- | --- |
| peace / fist / palm | 预训练模型，对应剪刀 / 石头 / 布，默认专注模式 |
| like / dislike / one | 预训练模型，切换“全部手势”启用 |
| ok / call / four / three / rock | 基于 21 个关键点的实验性几何规则，未经真实数据集准确率验收 |
| two | 与 peace 同形，统一输出 peace |
| stop | 与 palm 同形，统一输出 palm |
| grabbing / holy / timeout / xsign / hand_heart / take_picture / mute / stop_inverted | 待接入，页面明确标注，不伪造分类结果 |
| no_gesture | 无手、低置信度、未知手型、主结果双手歧义 |

注意：rock 是“摇滚手”，不是游戏里的石头（fist）。模型原生 ILoveYou 不映射为 rock。规则结果没有统计模型置信度，JSON 中 confidence 为 null；页面不显示虚构百分比。模型识别优先于扩展规则，不能保证四指等外观相近类别在所有角度均可分开。

想独立覆盖全部 22 类，需要先统一手型定义，收集不同左右手、视角、光照和遮挡样本，训练/验证专用分类器；grabbing 需要时序信息，mute 需要脸部上下文，双手类别需要联合建模。本版本未声称全类别识别已完成。

## Ubuntu 24.04 / RK3588 部署

这是浏览器 WASM CPU 路径，**未接入 RK3588 NPU，未在实际 RK3588 上验收，73 ms 不是已测得指标**。Ubuntu 版本本身不能保证摄像头、浏览器或板厂 GPU/NPU 驱动兼容。

在开发电脑构建：

```bash
npm run build
```

将整个 `dist/` 拷贝到板子，例如 `~/gesture-lab/dist/`。这个输出不包含 macOS 原生依赖，板子运行它无需 Node.js 或 npm。板子的 Ubuntu 桌面安装 Chromium（已有 Chrome/Chromium 可跳过安装）：

```bash
sudo snap install chromium
cd ~/gesture-lab/dist
python3 -m http.server 8080 --bind 127.0.0.1
```

**在板子自己的浏览器**打开 `http://localhost:8080`，此时读取的是板子连接的摄像头。Snap 版 Chromium 如果无法访问摄像头，可检查并连接 camera 接口：

```bash
snap connections chromium
sudo snap connect chromium:camera
```

构建产物已包含模型和 WASM，静态服务器启动后可离线识别。浏览器需要 WebAssembly、Web Worker、createImageBitmap 与 getUserMedia 支持。

局域网其他电脑访问板子网页时，getUserMedia 读取的是**访问者电脑**的摄像头，且局域网 IP 的普通 HTTP 不是安全上下文，会无法授权摄像头。远程访问需要可信 HTTPS；要从另一台电脑使用板子摄像头，则需要额外实现板端视频采集与传输服务，本版本不包含该服务。不要通过禁用浏览器安全策略解决。

### 性能实测

开启识别后页面显示单帧推理耗时、真实识别 FPS、手数及最近 300 次推理的 P95。采样上限约 15 FPS，设备慢时只处理最新视频帧，不排队积压。推理在独立 Worker，视频绘制在主线程。

“导出性能报告”包含最近最多 300 次推理的均值/P95、样本数、摄像头参数、浏览器和识别设置，便于迁移前后比较。推理耗时只覆盖 `recognizeForVideo`，不包括摄像头采集、ImageBitmap 传输、绘制和稳定等待时间。P95 ≤ 73 ms 仅表示该窗口推理指标达到参考目标，不表示端到端交互延迟 ≤ 73 ms。

建议同一分辨率 640×480 下分别测试空画面、单手、双手，每种至少持续 60 秒，预热后导出报告；另外记录温度、供电、浏览器版本、实际准确率和长时间运行稳定性。若 CPU 路径未达标，可调整采样/图像尺寸；仍不足则需要 RKNN 模型转换和板端服务，不能直接把 MediaPipe `.task` 当作 RKNN 模型运行。

## 接入游戏 / 输出协议

页面“结果 JSON”显示最新逐帧数据；主结果字段 `gesture` 在稳定前为 `no_gesture`。`hands[]` 是每只手的原始分类与关键点，没有做稳定判定。主结果仅单手有效。

```js
window.addEventListener('gesture-result', ({ detail }) => {
  if (detail.stable && ['peace', 'fist', 'palm'].includes(detail.gesture)) {
    console.log(detail.gesture, detail.confidence, detail.inference_ms)
  }
})
```

后续游戏应在回合结束时取稳定手势并锁定一次，避免每帧重复结算。本事件只在本页窗口发出，不是跨进程 API。摄像头关闭、后台暂停、重设参数及视频帧中断时会清空输出并发出 stable=false 的 no_gesture 事件。

## v0.2：侧向 / 朝镜头剪刀增强

默认开启“剪刀侧向增强”，在“剪刀石头布”和“全部手势”均生效，可以关闭进行对照。

- 模型输出低置信度或 None 时，用 `worldLandmarks` 的三维关节角度、手指伸直率与弯曲状态补充 peace 判断。要求食指/中指伸直，无名指/小指弯曲；检查骨段长度、坐标有效性和指尖分离，拒绝退化关键点。
- 不修改模型置信度阈值，不覆盖高置信度的冲突类别。补充结果 `source=rule, method=peace_3d, confidence=null`，界面显示“三维剪刀增强”。
- 同一只手分类短暂丢帧时最多保留候选至最后有效帧后 160 ms，丢失时间不计入保持时间；最近最多 8 帧至少 70% 为有效证据才确认。丢帧时仍输出 `stable=false`，手消失或检测到双手立即重置。
- JSON 与性能报告增加每手原始模型分类及三维关键点，便于分析“未检测到手 / 模型不确定 / 三维规则不匹配”。

这使用的是单目模型估计的三维关键点，并不是深度摄像头实测。两根手指完全重叠、严重遮挡或估计错误时仍可能失败；几何补充也可能误判。12 项测试验证合成关键点旋转、缩放、反例及时间逻辑，不等于真实摄像头准确率验收。可在同一光照下分别开/关增强，测试手掌正面、侧面、手指朝镜头及石头/布/单指/摇滚手反例。若仍不稳定，下一步应采集这些困难角度的真实样本做针对性训练。

## v0.3：停稳后剪刀石头布三选一

仅改变“剪刀石头布”模式，“全部手势”保留原有分类方式。

1. 用 21 个图像关键点的位移检测移动，按手掌大小和帧间隔归一化；同时对比停稳起点，检测缓慢位移。手腕移动、手指开合和朝向变化都会影响运动判定，允许小幅追踪抖动。
2. 移动、无手、双手或视频中断立即清空结果。手相对静止至少设定时间（默认 250 ms），且积累至少 3 帧，才输出候选；用最近最多 8 帧综合评分，不要求逐帧先命中同一个离散类别。
3. 模型返回完整类别分数，提取 Closed_Fist / Victory / Open_Palm；与世界坐标下四指开合程度对应的三种手型匹配分数融合，择优输出 fist / peace / palm。几何有效时权重为 75% 几何、25% 模型，最佳分至少 0.36，领先第二名至少 0.07；无有效几何时只用模型分，最佳分至少 0.22。这些是待实测校准的经验阈值，不是训练得到的概率。
4. 远离三类、候选接近或关键点无效时仍返回 no_gesture，不强行猜。界面显示“移动中 / 请停稳片刻 / 差异较大 / 已识别”，并显示三选一匹配度。

输出新增 `phase`、`match_score`、`candidates`。RPS 的 `source=rps`、`method=still_rps`、`confidence=null`；`match_score` 是经验综合匹配度，不是模型概率。`hands[]` 中的原始模型结果是诊断数据，游戏只能使用顶层 `stable=true` 的结果。

底层手部检测/模型推理仍持续运行，以判断移动；“移动不识别”指不确认、不发布有效手势，并非停止摄像头或停止底层推理。性能指标仍是模型推理时间，不含停稳等待。

新增 7 项测试，合计 19 项：移动清空、静止重判、手腕不动但手指改变、抖动容忍、未知类拒绝、弱模型评分与接近候选、掉帧恢复。测试使用合成关键点；真实手势效果仍需现场对照验证。部署包已同步更新。

## v0.3.2：页面可调停稳参数

剪刀石头布模式的“识别设置”增加三项参数，修改后即时重置本次确认状态：

| 参数 | 推荐值 | 数值变小 | 数值变大 |
| --- | ---: | --- | --- |
| 移动速度阈值 | 1.8 掌长/秒 | 更容易判为移动 | 更容易保留为停稳 |
| 累计位移阈值 | 0.22 掌长 | 小幅持续移动也会重置 | 可容许较大慢速位移 |
| 出手停稳时间 | 250 ms | 更快确认 | 等待更久再确认 |

当前推荐值比 v0.3.1 更严格。出现“动手时仍出结果”时，优先把移动速度阈值降至 1.4–1.6、累计位移阈值降至 0.16–0.20；若自然手抖导致不出结果，再逐步回调，每次只改一个参数。页面提供“恢复推荐值”。性能报告会保存三项参数，方便记录不同板子/摄像头的结果。

## v0.3.3：手指形状优先

三选一现在同时计算 3D 世界关键点和 2D 画面关键点的四指开合、关节伸直率、指尖到手腕的伸展距离，并选取能更清楚区分三种结果的坐标组。当手指几何证据明确时，占综合评分 85%，模型分类占 15%；这会让“食指和中指伸直、无名指和小指收起”的证据压过模型误报的 palm。2D 坐标也作为 3D 深度估计不稳定时的回退，因此更适合截图中这种正对摄像头的剪刀手。新增与错误 palm 模型结果冲突时仍选剪刀/石头的测试。

## v0.3.4：主手锁定与抗抖动停稳

剪刀石头布模式每帧选取最大的手掌作为主手，并在后续帧优先按空间位置和尺度继续跟踪该手。画面即使短暂出现第二只手（背景人物、误检或另一只手），也只显示并使用主手骨架进行三选一；这避免蓝绿两套骨架交替进入运动判断。

停稳检测只对运动信号使用指数平滑；识别手型仍使用未平滑关键点。单帧超过运动阈值时会暂时隐藏结果，但要连续两帧都检测为正常运动才重置停稳进度；极大位移仍会立即重置。这样关键点在特定角度的小幅跳动不会反复让“请停稳片刻”卡住。新增主逻辑回归测试，当前共 25 项。
